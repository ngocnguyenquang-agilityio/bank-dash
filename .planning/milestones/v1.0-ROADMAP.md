# Roadmap: bank-dash

## Overview

Two phases that migrate card number validation from a split client+server arrangement to client-side only. Phase 1 audits what currently exists so Phase 2 can make targeted, confident changes. Phase 2 delivers the complete improvement: real-time client feedback and removal of redundant server rules.

- Decimal phases (2.1, 2.2): Urgent insertions (marked with INSERTED)

## Phase Details

### Phase 1: Audit
**Goal**: Developer has a clear, documented picture of every place card number validation exists and what each rule does
**Depends on**: Nothing (first phase)
**Requirements**: AUDIT-01, AUDIT-02
**Success Criteria** (what must be TRUE):
  1. Developer can read a single reference listing every file that performs card number validation (client-side and server-side)
  2. Developer can see the specific rules each location enforces (length limit, character type, etc.)
  3. No validation location is ambiguous — each entry names the file, the mechanism, and the rule
**Plans:** 1/1 plans complete

Plans:
- [x] 01-01-PLAN.md — Audit all card number validation locations and produce VALIDATION-AUDIT.md

### Phase 2: Implement
**Goal**: Users get immediate inline feedback on card number input, and the backend no longer enforces card number rules
**Depends on**: Phase 1
**Requirements**: CLIENT-01, CLIENT-02, CLIENT-03, SERVER-01, SERVER-02
**Success Criteria** (what must be TRUE):
  1. User cannot type more than 16 digits into the card number field — the field rejects additional input or shows an inline error before submission
  2. User cannot enter non-numeric characters into the card number field — they are prevented or immediately flagged
  3. User sees validation feedback without the page making a server request (no round-trip for card number rules)
  4. Card creation and update still succeed end-to-end after server-side validation rules are removed
  5. No card number validation logic remains in the Strapi backend
**Plans:** 2/2 plans complete

Plans:
- [ ] 02-01-PLAN.md — Add Schema.pattern validator to CardFormSchema with TDD tests for inline validation
- [ ] 02-02-PLAN.md — Remove regex validator from Strapi card schema and verify no regression
