# Requirements: bank-dash

**Defined:** 2026-03-20
**Core Value:** Users can view and manage their cards and transactions with immediate, accurate feedback when entering card data.

## v1 Requirements

Requirements for this milestone. Each maps to a roadmap phase.

### Validation Audit

- [x] **AUDIT-01**: Developer can see all locations where card number validation exists (client-side and server-side)
- [x] **AUDIT-02**: Developer can see what rules each validation enforces (length, format, etc.)

### Client-Side Validation

- [x] **CLIENT-01**: User sees an error if card number exceeds 16 digits (validated client-side before submission)
- [x] **CLIENT-02**: Card number input prevents or rejects non-numeric characters
- [x] **CLIENT-03**: Validation feedback is shown inline (real-time or on submit) without a server round-trip

### Server-Side Cleanup

- [x] **SERVER-01**: Strapi backend does not perform card number validation (all rules removed)
- [x] **SERVER-02**: Removing server-side validation does not break existing card creation or update flows

## v2 Requirements

Deferred to future — not in current scope.

### Enhanced Validation

- **ENH-01**: Luhn algorithm check for mathematically valid card numbers
- **ENH-02**: Card type detection (Visa/Mastercard/Amex) from prefix

## Out of Scope

| Feature | Reason |
|---------|--------|
| Server-side card number validation | Moving to client-side only for better UX |
| Other field validations (expiry, CVV) | Not in current scope |
| Card type brand icons | Not requested |
